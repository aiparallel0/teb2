Great question — this is a topic I find genuinely interesting. Let me break down the philosophy and tooling for building brutally efficient frontends.## The core philosophy: subtraction is the skill

Most of the modern web is slow not because browsers are slow — it's because developers ship megabytes of JavaScript to do things HTML and CSS do for free. A 90s machine running a well-written C app could absolutely match the interactivity of most React sites today, because the React site is burning cycles on a virtual DOM, a module bundler runtime, and layers of abstraction that add nothing to the user.

The guiding principle is: **use the least powerful tool that solves the problem correctly.**

---

## Tier 1 — C99 / WebAssembly (for true performance-critical work)

If you need raw compute — image processing, game engines, codecs, physics simulations — C99 compiled to WebAssembly via **Emscripten** is the answer. It runs within a few percent of native speed in the browser. You can also target desktop natively with **raylib** or **SDL2**, and the exact same C code compiles to both. This is the tier that runs on anything with a CPU.

Why C99 specifically: it's the most portable, most toolchain-supported standard. C11 and C17 are fine too, but C99 has virtually universal compiler support including on ancient embedded targets.

---

## Tier 2 — Vanilla HTML/CSS/JS (the sweet spot for most UIs)

This is underrated and massively underused. What modern browsers give you for free is astonishing:

- **CSS Grid and Flexbox** — complex layouts, zero JS
- **CSS custom properties** — live theming, animation, reactive variables
- **Web Components** — reusable encapsulated components, no framework
- **`fetch` + `IntersectionObserver` + `ResizeObserver`** — async data loading, lazy rendering, responsive layout changes
- **CSS `@keyframes`** — smooth animations, no JS animation library
- **`<dialog>`** — native modal with focus trapping, no JS modal library needed
- **`<details>/<summary>`** — accordion, free

A complete, polished, interactive web app can be built here with a total bundle under 50 KB. It loads instantly on a 3G connection and runs fine on a 10-year-old phone.

---

## Tier 3 — Minimal frameworks (only when you can prove the need)

If you genuinely need a component model at team scale, reach for the **lightest option that works**:

- **Preact** — 3 KB React-compatible drop-in
- **Svelte** — compiles to vanilla JS, ships zero framework runtime
- **Solid.js** — fine-grained reactivity, no virtual DOM diffing
- **htmx** — server-rendered HTML with declarative AJAX, ~14 KB, almost no JS you write
- **Alpine.js** — sprinkle reactivity on existing HTML, ~15 KB

Avoid: React (45 KB+ just for the runtime), Next.js (enormous cold start), Angular (framework-in-a-framework), anything that requires a 500 MB `node_modules` folder to render a button.

---

## What kills performance (the avoid list)

- Client-side routing when the server can route
- JavaScript for layout/positioning (use CSS)
- JavaScript for animations (use CSS transitions/keyframes)
- Bundling unused code (tree-shake or just don't import it)
- Loading fonts from CDN with no `font-display: swap`
- Not setting `width`/`height` on images (causes layout shift)
- `npm install` a library for something that's 3 lines of JS

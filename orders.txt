1. SSE — complete api/sse.c + main.c fork
══════════════════════════════════════════
Problem: handle_sse_subscribe() returns immediately; main.c closes conn after
one response; no ws_id scoping; SseConn is never used.

Fix main.c:
  After resp = dispatch(req, &ctx);
  if resp.status == 0 (SSE hijacked), do NOT call write_response() or
  close(conn) — the forked child owns the fd. Otherwise write_response +
  close as today.
  Before dispatch(), fork(). In the child: drop srv fd (close(srv)), run
  dispatch, then _exit(0). In the parent: close(conn), continue loop.
  Use SIGCHLD with SIG_IGN to reap children automatically:
    signal(SIGCHLD, SIG_IGN);

Replace api/sse.c entirely:
  handle_sse_subscribe(HttpReq req, Ctx *ctx):
    - Auth check (existing pattern, return json_error 401/403 on fail)
    - Parse ws_id: strtoll(req.path + 8, NULL, 10)  (path: /sse/chat/<ws_id>)
    - Write SSE headers directly to req.fd:
        "HTTP/1.1 200 OK\r\n"
        "Content-Type: text/event-stream\r\n"
        "Cache-Control: no-cache\r\n"
        "Connection: keep-alive\r\n"
        "Access-Control-Allow-Origin: *\r\n"
        "\r\n"
    - SseConn c = {req.fd, 1};
    - int64_t last_id = 0;
    - Loop while c.open:
        sleep(2);
        q.ws_id = ws_id; q.cursor = last_id; q.limit = 16;
        r = list_chats(ctx->db, q);
        for each row: build json buf; sse_write(&c,"message",buf);
                      last_id = row.id;
    - Return zeroed HttpResp (status=0 signals caller to skip write_response)

Add int fd to HttpReq in core/types.h.
Populate req.fd = conn in main.c before calling parse_request().

Rename existing /events route in api/server.c to /sse/chat/ prefix:
  strncmp(p, "/sse/chat/", 10) == 0 && GET → handle_sse_subscribe

ChatQuery must have int64_t cursor field (needed for item 5 below, but add it
